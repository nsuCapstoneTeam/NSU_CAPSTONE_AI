# 0006. 음악 입력 동기 처리와 AI 선설계

## 상태와 결정 이력

2026-10-03 비동기를 검토했으나 사용자의 후속 지시로 동기로 변경했다.
현재 결정은 **① AI에서 먼저 설계하고 동기로 처리**하는 것이다.
기존 파일 경로는 링크 호환을 위해 유지한다.
ADR 0003의 동기 생성 원칙을 유지하며 큐·worker를 요구하지 않는다.

## 처리 방향

등록은 전처리·임베딩 생성·DB 저장 완료 후 결과를 반환한다.
검색은 입력 임베딩 생성·저장 후보 벡터 비교 완료 후 결과를 반환한다.
실패 시 실패 응답을 반환하며 접수만 성공한 상태를 완료로 취급하지 않는다.
현재 `AudioEmbeddingStorage.store()`와 `DatabaseAudioSearch.search()`는 동기 함수다.
프로세스 내부 생성 잠금은 난수 상태 보호를 위해 유지한다.
동기 방식이 모든 요청의 직렬 처리를 의미하지 않으며 처리량은 실행 환경에 따라 달라진다.
HTTP 타임아웃·동시 요청 제한·재요청 정합성은 업무 API 구현 시 검토한다.

## 후속 작업

[연동 계약 초안](../api/AUDIO_JOB_CONTRACT.md)을 백엔드와 검토한다.
원본 ID·파일 참조·버전·수정/삭제·오류 계약은 제안 단계이며 업무 API는 구현 전이다.
Text 번역 방식은 이번 결정에 포함하지 않는다.
외부 Linear·GitHub 이슈는 이번 작업에서 변경하지 않았다.

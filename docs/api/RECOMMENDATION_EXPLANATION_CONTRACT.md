# 곡별 추천 이유: 현재 책임과 상세 계약 제안

## 상태와 기준

현행 책임은 [Accepted Linear 서버 협의 012](https://linear.app/nsu-capstone/document/012-clap-음악-유사도-기반-곡-추천-흐름-c7c809f92cba) §6.2를 따른다. 별도 AI Explanation API 호출 범위는 012가 대체했다. Spring이 AI의 구조화된 상세 정보·행사 요청 해석 결과·실제로 통과한 필수 조건으로 템플릿 추천 이유를 만든다. LLM은 필수가 아니다.

검색 응답은 raw cosine 순위로 최대 100곡을 반환하고 Spring은 순서를 다시 정렬하지 않는다. 별도 AI 설명 호출은 하지 않는다. 이 문서는 Spring template에서 사용할 근거와 아직 정하지 않은 세부 필드의 설계 참고이며 확정 DTO/Schema가 아니다.

아래 접힌 내용은 2026-10-05의 역사적 설계 제안이다. 제안 당시의 별도 AI 호출·Spring Ranker·항목 점수·후보 비교 방안은 Accepted 012의 현행 정책이 아니며, 제안 원문은 이력 보존을 위해 유지한다.

## 곡별 설명 흐름과 제안 정보

1. AI가 raw cosine 순으로 최대 100곡과 구조화된 상세 정보·행사 요청 해석 결과를 반환한다.
2. Spring이 AI의 상세 정보·해석 결과 및 실제 통과한 필수 조건으로 곡별 템플릿 추천 이유를 구성한다.
3. Spring은 추천 결과 순서를 유지하고 추천 결과와 함께 설명을 저장·응답한다.

세부 설명 schema·저장 field는 API 구현에서 정합화한다. 외부 결과는 단일 `resultVersion`으로 식별하고, AI 내부 생성/전처리·변환·분석·요청 해석 버전은 별도 추적한다.

| 제안 정보 | 목적 |
| --- | --- |
| 결과 식별자·버전, music_id·audioRevision | 다른 곡/오래된 결과의 설명 혼입 방지 |
| 곡별 유사도·유효 항목 점수와 사유 | 실제 계산 근거 사용 |
| 실제 통과한 필수 조건 | 확인되지 않은 PASS 추정 방지 |
| 공개 가능한 곡·Artist 연결 정보 | 곡별 설명 연결; 아티스트 점수 집계 없음 |

필드명·필수 여부·최대 설명 대상 수는 확정 Schema가 아니다.
비교 대상 Artist, 아티스트 집계 점수, 항목 diff, 후보 비교 문장은 현행 입력/출력 계약에서 제외한다.

## 생성·실패 원칙

- 템플릿 설명은 Spring 책임이며 LLM은 필수 구성요소가 아니다.
- [Superseded for ranking 009](https://linear.app/nsu-capstone/document/009-종합-적합도의-항목-구성-85e281c843cd)에서 유지된 세부 정보 누락의 `null`과 사유 구분을 적용한다. BPM/Rhythm은 음악 순위 점수로 쓰지 않는다.
- 실제 유사도·점수·필터 결과만 설명하고 누락을 0/PASS로 추정하지 않는다.
- 신뢰성·위험 신호를 음악 순위의 원인으로 설명하지 않는다.
- 곡별 추천 이유를 후보 간 점수 차이 문장으로 만들지 않는다.
- 반환된 유사도 순위를 설명 때문에 재계산하지 않는다.
- AI 검색 실패·timeout은 별도 설명 호출 실패와 구분해 [Accepted 010](https://linear.app/nsu-capstone/document/010-ai-곡-검색-실패시간-초과-시-추천-api-응답-46a63dece138)을 따른다.

## 남은 계약·검증

- [ ] Spring 템플릿에 쓰는 구조화된 근거·설명 필드의 schema 정합화
- [ ] 결과와 단일 `resultVersion` 연결 field 정합화
- [ ] 정상·누락·오래된 결과의 설명 evidence 처리 검증
- [ ] 실제 처리시간 측정; 측정 전 성능 목표 임의 확정 금지

기본 방향의 합의 전 표시는 당시 제안이며 현행 작업 기준으로 사용하지 않는다.
당시 후보 비교 관련 이슈 링크도 이력이다.

## 상태

Proposed — 2026-10-05 AI 협의 3/9에 대한 AI 측 권장안. 백엔드 합의 전이며 구현 전이다.
설명 생성의 AI 책임은 [ADR 007](../adr/server-agreements/007-recommendation-scoring-and-explanation-responsibilities.md)을 따른다.
이 문서는 상세 호출 계약 제안으로, 확정된 ADR의 책임 분담을 변경하지 않는다.
엔드포인트·DTO·timeout·성능 목표는 아직 확정하지 않는다.

## 권장 방식과 이유

A 방식: Spring이 최종 순위를 확정한 후 AI 설명 기능을 추가 호출한다.
초기에는 LLM 없이 한국어 템플릿으로 실제 점수와 차이를 문장으로 표현한다.
검색 시점에는 최종 아티스트 순위를 알 수 없으므로 최종 선정 이후 설명한다.
템플릿은 수치와 표현의 일치 여부를 검증하기 쉽다. 추가 HTTP 호출 비용은 발생한다.

대안 B는 Spring이 비교 문장을 생성하므로 기존 AI 설명 책임을 변경해야 한다.
추후 LLM을 도입하더라도 수치·차이·선정 근거는 코드로 확정하고 LLM은 표현만 담당한다.
LLM 도입 여부와 모델은 미정이며 현재 실측 지연시간은 없다. 초 단위 응답 시간을 약속하지 않는다.

## 입력부터 출력까지

1. Spring이 Eligibility Filter 결과와 ACTIVE 후보 쌍을 구성한다.
2. AI가 유사 곡 50~100개와 항목 점수를 반환한다.
3. Spring이 곡→아티스트 집계·종합 점수·최종 Top10을 확정한다.
4. Spring이 최종 선정 결과와 설명 근거를 AI에 전달한다.
5. AI가 검증 가능한 항목 차이를 계산하고 템플릿 설명을 반환한다.
6. Spring이 같은 선정 결과에 설명을 연결해 서비스 응답을 구성한다.

설명 요청에서는 음원을 다시 분석하거나 최종 순위·종합 점수를 재계산하지 않는다.
동기 추가 호출과 화면에 먼저 점수를 표시한 뒤 설명을 보충하는 방식 중 어느 것을 사용할지는 미정이다.

## Spring이 전달할 정보 제안

| 정보 | 사용 목적 |
| --- | --- |
| 추천 결과 식별자·버전 | 다른 요청이나 오래된 결과의 설명이 섞이지 않도록 연결 |
| 아티스트 식별자·최종 순위·종합 점수 | Spring의 선정 결과 그대로 설명 |
| 아티스트별 집계된 항목 점수·유효 여부·점수 기준 버전 | 곡 점수가 아닌 최종 집계 기준으로 비교 |
| 실제 필터 결과와 공개 가능한 사유 | 확인되지 않은 일정·지역·예산 충족을 주장하지 않도록 제한 |
| 집계 방식·점수 기여도 또는 구조화된 선정 근거 | 특정 항목이 최종 선정에 기여했다는 설명의 근거 |
| 비교 대상 아티스트 | 어떤 후보 사이의 차이를 설명할지 지정 |
| 신규 노출 대상과 노출 정책 근거(있는 경우) | 음악 적합도와 신규 노출 사유를 구분 |

민감한 개인정보와 불필요한 원본 자료는 전달하지 않는다.
구체 필드명, 필수·선택 구분, 최대 대상 수, 비교 조합은 백엔드와 합의한다.

## 설명 생성 규칙

AI 측 음악 항목은 [ADR 008](../adr/server-agreements/008-music-score-items-and-performance-format.md)의
의미·BPM·리듬 기준을 따른다. 음악 스타일을 별도 공연 스타일 점수로 중복 설명하지 않는다.
공연 형태는 Spring이 전달한 실제 비교·필터 결과로만 설명한다. 팀 전체 반영은 별도 확인한다.

- 같은 의미·범위·기준 버전의 유효 항목끼리만 차이를 계산한다.
- 누락 점수를 0점으로 바꾸거나 누락된 필터 결과를 PASS로 추정하지 않는다.
- 설명에 표시하는 차이는 화면 점수의 반올림 기준과 일치해야 한다. 기준은 미정이다.
- 단순히 높은 항목을 발견했다는 이유로 “이 항목 때문에 1위”라고 단정하지 않는다.
  인과 설명은 Spring이 전달한 선정 근거·기여도로 뒷받침되어야 한다.
- 동점, 불완전한 근거, 비교 불가능한 항목에서는 순위 차이를 임의로 설명하지 않는다.
- 신뢰성·위험 신호를 순위 선정 이유로 사용하지 않는다.

표현 예시(실제 관측 결과가 아님):

> 2위 후보보다 의미 적합도가 7점, BPM 적합도가 12점 높습니다.

이 문장은 항목 차이 설명이며 그 차이만으로 최종 1위 선정의 원인을 주장하지 않는다.

## 응답 정보 제안

추천 결과 식별자·버전과 대상 아티스트 식별자에 연결해 추천 이유,
비교 대상·항목별 차이·비교 문장 및 설명 생성 상태를 반환한다.
AI 응답에서 최종 순위나 종합 점수의 새 값을 생성하지 않는다.
Spring은 설명이 현재 추천 결과와 일치하는지 확인한 뒤 연결한다.

## 실패 처리 제안

설명 실패·timeout이 이미 계산된 Top10과 점수를 무효화하지 않도록 한다.
Spring은 추천 결과를 유지하고 설명 생략 또는 승인된 기본 문구를 사용한다.
실패 시 근거 없는 성공 설명을 반환하지 않는다. 부분 설명 허용, timeout,
재시도 및 기본 문구는 별도 합의한다.

## 신규 아티스트 설명 제안

신규 슬롯이 실제 운영되고 대상이 선정된다면 설명도 제공하는 것을 권장한다.
음악 적합 근거와 “신규 아티스트 노출 정책에 따른 표시”를 구분한다.
신규 여부·슬롯 선정·정책값은 Spring 책임이며 AI가 추정하지 않는다.
이번 제안으로 신규 전용 추가 검색 계약이나 슬롯 정책을 확정하지 않는다.

상태: **AI 측 초안, 백엔드 검토 전, 업무 HTTP API 구현 전**.
2026-10-03 사용자 결정: ① AI에서 먼저 설계하고 동기 방식으로 처리한다.
기존 파일 경로는 링크 호환을 위해 유지한다. 아래 계약은 검토용 제안이다.

2026-10-04 구체화한 [백엔드 전달용 권장안](AUDIO_SYNC_BACKEND_HANDOFF.md)을 우선 검토한다.
파일 직접 전달과 등록·교체 통합 PUT을 권장하므로 아래 source_ref·POST 분리는 초기 제안 이력이다.

## 책임과 데이터 연결

백엔드는 음악 ID 발급, 아티스트 소유 관계, 인증/인가와 파일 보관을 담당한다.
AI는 공통 생성기로 임베딩을 생성·저장·검색한다.
백엔드는 결과 music_id를 실제 음악·아티스트 정보에 연결한다.
아티스트 개인정보를 벡터 테이블에 복제하지 않는다. 등록 음악에는 행사 요청 ID가 필요하지 않다.

| 필드 | 제안 규칙 |
| --- | --- |
| music_id | 백엔드 ID의 문자열 표현. 현재 저장 코드는 앞뒤 공백 없는 1~200자 사용 |
| source_ref | 처리 중 AI가 접근할 파일 참조. 저장소·접근 권한 협의 필요 |
| source_sha256 | 원본 바이트의 SHA-256. 전달 시 실제 파일과 일치 여부 검증 |
| source_version | 음악별 증가하는 파일 버전. 수정·삭제 순서 검증 제안이며 현재 미구현 |
| search_request_id | 검색 요청 추적용 식별자 제안. 등록 음악 ID와 구분 |

파일 이름이나 아티스트 이름을 음악 ID로 사용하지 않는다.
해시는 음악 ID를 대체하지 않으며 같은 파일을 여러 음악 ID가 사용할 수 있다.
제목 등 오디오 내용과 무관한 수정에는 임베딩을 재생성하지 않는다.

## 동기 처리 흐름

```text
등록: 파일 보관·음악 ID 전달 → 전처리·임베딩 생성 → DB 저장·커밋 → 완료 응답
검색: 검색 파일 전달 → 입력 임베딩 생성 → 저장 후보 벡터 비교 → Top5 결과 응답
```

요청은 완료 또는 실패까지 기다리며 접수만 완료한 상태를 성공으로 반환하지 않는다.
검색 입력을 후보 음악으로 저장하지 않고 후보 벡터도 매번 재생성하지 않는다.
큐·worker·job_id·대기 상태·작업 상태 조회 API는 이번 계약에서 제외한다.
동기 방식 자체가 모든 사용자 요청의 직렬 처리를 의미하지 않는다.
현재 생성기의 프로세스 내부 잠금은 난수 상태 보호를 위해 유지한다.

## 내부 API 제안

다음 업무 API는 아직 구현되지 않았다. 인증된 백엔드의 내부 호출로 제안한다.
사용자의 임의 로컬 경로 입력을 허용하지 않으며 파일 참조 검증·서버 간 인증은 협의한다.

| 요청 | 성공 응답 제안 |
| --- | --- |
| POST /internal/audio-embeddings | 저장 완료 후 201, 동일 결과가 이미 있으면 200 |
| POST /internal/audio-search | 검색 완료 후 200과 Top5 결과 |
| PUT /internal/audio-embeddings/{music_id} | 갱신 완료 후 200; 현재 갱신 미구현 |
| DELETE /internal/audio-embeddings/{music_id} | 삭제 완료 후 204; 현재 삭제 미구현 |

등록 입력은 music_id·source_ref·원본 해시·파일 버전으로 제안한다.
검색은 별도 파일 참조·원본 해시와 선택적인 search_request_id를 전달한다.
검색 결과는 음악 ID·순위·원시 코사인 유사도·표시 점수를 기반으로 설계한다.
표시 점수는 임시 유사도 지표이며 종합 적합도나 신뢰 확률이 아니다.

## 정합성·실패·재요청

- 현재 같은 ID의 동일 해시·생성 조건·벡터는 중복 저장하지 않는다.
  같은 ID에 다른 결과가 있으면 충돌로 거부하며 자동으로 덮어쓰지 않는다.
- 갱신은 새 벡터 생성 후 현재 버전 확인·교체를 원자적으로 수행하도록 제안한다.
  오래된 요청이 최신 값을 덮어쓰거나 삭제한 음악을 재등록하지 않도록 버전 검증이 필요하다.
  갱신·삭제 규칙은 현재 미구현이다.
- 백엔드 파일 교체와 AI 저장은 하나의 트랜잭션이 아니므로 실패 시 복구·노출 정책을 합의한다.
  이전 파일 벡터를 새 파일의 결과로 표시하지 않는다.
- HTTP 시간 초과는 DB 저장 실패를 보장하지 않는다. 재요청 전 저장 상태·버전 확인 계약이 필요하다.
- 오류 사유는 분류 가능하게 제공하고 비밀번호·접속 문자열·스택은 노출하지 않는다.
- 입력 오류는 수정 없이 재시도하지 않는다. 일시적 실패 재시도·타임아웃·동시 요청 제한은 협의한다.
- 파일은 처리 완료까지 접근 가능해야 한다. 검색 파일 보관 기간은 백엔드와 협의한다.
